# 清晰度增强模块说明


## 1. 现在这模块做了什么

这块功能是给数字人生成视频做清晰度增强的。

现在的流程还是离线为主：

1. 先跑动作素材、TTS、Wav2Lip 口型
2. 再把生成结果拿去做增强
3. 最后导出一个更清楚的视频

它现在还不是实时增强，也没有直接插进 `/alpha/speak` 的实时画面。

### 前端已经加了什么

生成视频区域里现在能选增强方式：

- `不增强`
- `realesr-animevideov3 局部增强`
- `realesrgan-x4plus-anime 局部增强`
- `clear_reality_x4.onnx（ONNX）`

同时还加了几个和生成相关的选项：

- `最大生成帧数`
- `不限制帧数，按音频长度生成`
- `视频库`
- `实时增强实验开关`

其中“实时增强实验开关”现在只是一个保留入口，保存配置会生效，但默认流程还不会把 RealESRGAN 接到实时帧里。

### 后端已经接了什么

后端已经把增强接进了离线生成流程。

现在主要相关接口是：

- `POST /render/video-task`
- `GET /render/tasks/{task_id}`
- `GET /render/output/{task_id}`
- `GET /render/library`
- `GET /render/realtime`
- `POST /render/realtime`

生成的时候会根据 `enhance_mode` 走不同组合：

- `wav2lip256 + realesr-animevideov3`
- `wav2lip256 + realesrgan-x4plus-anime`
- `onnx_base + clear_reality_x4`

后端也做了组合限制，避免选到不支持的搭配：

- `wav2lip256` 才能配 `realesr-animevideov3` / `realesrgan-x4plus-anime`
- `onnx_base` 只保留 `none` 或 `clear_reality_x4`

### 现在增强是怎么做的

现在不是整帧粗暴增强，而是尽量只增强嘴部附近的小区域。

这个区域来自动作素材里的检测框和 `coords.pkl`，增强完以后再贴回原帧。

这样做的好处很直接：

- 比整帧增强快很多
- 不容易把背景也一起磨糊
- 更适合现在这条主线

所以这一步现在更像“离线局部增强”，不是实时美颜。

## 2. 现在这条线已经到什么程度了

这条线现在已经跑通过，能实际用：

- 256 Wav2Lip 主线
- `realesr-animevideov3` 局部增强
- `realesrgan-x4plus-anime` 局部增强
- `clear_reality_x4` ONNX 实验路线

也确认过几件事：

- `不增强` 会更快
- 局部增强比整帧增强快很多
- 增强本身还是会明显增加生成时间

现在生成视频会落到：

```text
tmp/render_outputs/<task_id>/render.mp4
```

前端新做的“视频库”就是从这里读历史结果。

## 3. 现在还不能叫实时增强

因为现在这套流程还是离线的，里面还要经过这些步骤：

- 读完整视频
- 切帧
- 跑 Wav2Lip
- 跑增强
- 再合成视频

所以现在它还不能直接拿来做实时画面。要是真要往实时走，后面还是得把增强节点单独拆出来，再把延迟和回退逻辑补上。显卡更强的话，这条路才更有机会做成实时的。


## 4. 如果后面要往实时做，建议怎么接

我们现在更倾向于把它往实时方向做，所以后面建议按这个顺序来。

### 4.1 先把实时帧链路单独拎出来

要先找到实时视频输出经过的那条链路。

现在主线大致是：

```text
alpha/speak -> TTS -> 数字人生成 -> 视频帧输出
```

以后要做实时增强，就要在“视频帧输出”这条链路上单独插一个增强节点。

这个节点最好是：

- 独立函数
- 独立开关
- 独立日志
- 出错的时候可以直接跳过

不要一开始就把增强绑死在主渲染流程里。

### 4.2 先只做小区域增强

实时场景里不建议整帧增强。

更适合的做法还是沿用现在这条路，只增强嘴部或者下半脸一小块：

- 先拿检测框
- 再从检测框里裁 ROI
- 只对 ROI 做增强
- 最后贴回原帧

这样延迟会小很多，也更容易先跑起来。

### 4.3 把增强做成“可退回”的

实时增强最怕卡住。

所以这个模块后面一定要留退路：

- 增强超时就跳过
- GPU 忙的时候直接降级成不增强
- 任务过长就不要堆太多队列

它更像一个可选滤镜，不像主流程必须依赖的步骤。
